# 编译与运行说明

## 环境

比赛核心：Ubuntu 22.04、g++ 11.4、C++17 标准库。UI 与辅助脚本：Python 3.10 以上。无需第三方 C++、Python 或 JS 库。

## 构建

```bash
bash build.sh
# 或 CMake（开发与测试）
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j2
ctest --test-dir build --output-on-failure
```

Windows 本地可使用 MinGW：

```powershell
g++ -std=c++17 -O2 -I include src/main.cpp src/parser.cpp src/router.cpp -lshell32 -o outputs/router.exe
```

Windows 入口用系统 Unicode 命令行转换为 UTF-8，文件路径使用 `std::filesystem::u8path`，支持中文与空格。

## 标准 CLI

```bash
bash run.sh --def input.def --lef input.lef --thermal-report thermal.json --output output.guide
```

可选参数：`--metrics`、`--trace`、`--config`、`--time-limit`、`--iterations`、`--trace-limit-mb`。标准四参数无需 UI、Python、参考 Guide 或配置文件。
新增可选 C++ 参数：`--progress-dir <新目录>` 启用 progress.log/jsonl；`--progress-every 1000`、`--monitor-interval 5`、`--heartbeat-interval 10` 分别控制位置采样、协作式资源采样与检查点心跳。直接 Linux CLI 使用 `/proc/self`，Windows 无法读取的 Linux 指标为 N/A；日志失败尽量降级，不改变路径算法、Guide 格式或四参数提交接口。
不可达、无引脚、非法层、缺失 Via、超预算、未知配置等均返回非零。全部 Net 成功且内部验证后才写出 Guide。

## 本地流程

```powershell
python scripts/run_case.py --case sample001 --backend wsl --label run01 --trace
python scripts/evaluate.py --case sample001 --label run01 --backend wsl --engine latest
python ui/app.py --port 8501
```

`--backend wsl` 使用已经安装的 Ubuntu，不安装或修改 WSL。Linux 主机用 `--backend native`。
`--label` 不能复用已有运行；对比使用 `--config configs/baseline.json --label baseline01`。
指定输入可用 `--def`、`--lef`、`--thermal-report`；额外参数见脚本 `--help`。

本地脚本默认启用监控，即使没有 `--trace`，仍在 `outputs/runs/<case>/<label>/` 保存阶段进度、资源 CSV 与 HOST 记录。Windows Python 启动 WSL；Linux Supervisor 启动并等待 Router、读取 Router PID 的 `/proc`，HOST 另行记录子进程和文件更新时间，不反复新开 WSL。资源采样不重复执行；GNU time 最终峰值与周期观察到的 Router 峰值分开解释。

Python 支持 `--progress-every`、`--monitor-interval`、`--heartbeat-interval`，并自动为 C++ 填入 `--progress-dir`；Python 本身不接受 `--progress-dir`。`--stall-after 30` 设置宿主 NO_PROGRESS 阈值并参与 Linux 监督租约计算，`--no-monitor` 只关闭新增监控而不关闭显式 Trace，二者不能传给 C++。

实时查看示例（PowerShell；标签改成实际运行，按 Ctrl+C 仅停止查看）：

```powershell
Get-Content -LiteralPath 'outputs/runs/sample001/run01/progress.log' -Encoding UTF8 -Wait -Tail 20
```

`run.json` 先记录 RUNNING，正常收尾后更新 ROUTED/FAIL、失败类别/证据与最后阶段/Net。Linux 的 router_process/router_exit 记录、HOST 租约及按需取消文件并非每次都齐全；启动失败、WSL 中断或写入不可用时可能缺失。仅有退出码 1/137、代理警告、空 time 文件或 NO_PROGRESS 都不足以确认 OOM/死锁。所有运行目录（包括只留下部分日志的失败目录）均不能复用标签。

## 独立提交包

```bash
python scripts/package_submission.py --with-linux-binary
unzip outputs/submission_v1.zip -d outputs/unpacked
cd outputs/unpacked
bash build.sh
bash run.sh --def /path/input.def --lef /path/input.lef --thermal-report /path/thermal.json --output /path/output.guide
```

解压后入口直接位于根目录。`run.sh` 使用脚本自身路径定位程序，不依赖调用者当前工作目录。ZIP 中 Shell 文件保留 Unix 执行权限。
正式平台的评分、隐藏用例与资源硬性约束仍需独立验证。
