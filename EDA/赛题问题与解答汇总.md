### Q7. sample001 文件组成及与 Open3DBench 的关系

**问题：**

公开用例的结果格式是否和Open3Dbench的placement结果格式一致？

**解答：**

sample001 包含三类文件：

1. 全局布线输入文件：`sample001.input.def`、`sample001.input.lef`、`sample001.thermal.input.json`。

   DEF 和 LEF 与 Open3DBench 的 placement 输出一样：DEF 包含上下放置的两个 Die；LEF 基于 Nangate45 改写，上下 Die 有各自对应的 Macro，用 `_bottom`、`_top` 后缀区分。

   原答复还指出：DEF 中 `RESOURCE_SLOT_botttom` 和 `RESOURCE_SLOT_top` 的实例是预留 TSV 槽位，全局布线要为跨 Die Net 选取合适的槽位以获得最优性能。这是历史说明，后续取消槽位的更新见补充说明。

2. 全局布线输出文件：`sample001.output.guide`。

3. 评分程序输出文件：`evaluation_report.json`。

**来源：** 官方 Q&A（原 Q14 [0905]）。

**补充说明：**

**版本差异：** 原答复包含预留 `RESOURCE_SLOT` 的历史方案；后续官方原 Q30、Q34、Q90 明确移除了 slot 内容。保留旧说明供追溯，不能据此要求当前只能在槽位布 TSV。`RESOURCE_SLOT_botttom` 为原文拼写（包含三个 t），本汇总不擅自改名。

### Q16. LEF RECT 的两个顶点是否必须按最小值在前排列

**问题：**

case005的lef文件里面，有两个RECT坐标的 yMin > yMax，问一下这个问题是为啥？

**来源：** 官方 Q&A（原 Q46 [10.13]）。

**补充说明：**

### Q17. case005 的 DEF TRACKS 与 LEF PITCH 不一致

**问题：**

想确认 case005 的轨道间距：
3DIC全局布线公开用例说明_20260930.docx 的“三、工艺说明”写 metal9、metal10、metal19、metal20 间距为 1.0 µm，并说明 DEF TRACKS 与 LEF PITCH 对齐。
`open_3d_case005.input.lef` 第205、226、429、450行确实是 PITCH 1.00 1.00。
但 `open_3d_case005.input.def` 第671～674行的 TRACKS 均为 STEP 500，第12行单位为2000 DBU/µm，换算后间距是 0.25 µm。
请问这处差异是有意设置的吗？布线器估算容量时，是否应按评分说明，以 DEF TRACKS 的 0.25 µm 为准？

**解答：**

DEF TRACKS 与 LEF PITCH 不会完全对齐，文档有误，后续改正。布线器估算容量时，以 DEF TRACKS 的 0.25 µm 为准。

**来源：** 官方 Q&A（原 Q57 [10.14]）。

**补充说明：**

原问题的单位换算为：

$$\frac{500\ \mathrm{DBU}}{2000\ \mathrm{DBU}/\mu\mathrm{m}}=0.25\ \mu\mathrm{m}.$$

保留官方确认的 DEF TRACKS 口径，不将 LEF PITCH 的 1.00 μm 擅自写回输入文件。

### Q19. 宏朝向、ORIGIN、PIN 与 OBS 的几何复杂性

**问题：**

是否可能出现八种宏朝向、非零ORIGIN、非矩形PIN/OBS、多PORT、多形状引脚?

**解答：**

朝向不会有8种，只是水平或者垂直，还有上下层。这几个方向。非零ORIGIN是可能的。非矩形的 pin，它的 pin 跟 OBS 它都是多个矩形可能是多个矩形去组合起来的。最终 pin 的形状它不一定是一个矩形，它可能是确实是组成了一个比较不规则的图形。然后一个 pin 确实可能有多个 port，并且这个 pin它可能还可能存在于多层，而不是单单存在于一层。

**来源：** 官方 Q&A（原 Q97）。

**补充说明：**

原答复对朝向的描述为“水平或者垂直，还有上下层”，没有列出 DEF 的具体方向枚举；不能据此自行映射为一套完整 orientation 列表。原答复中的“abs”按上下文保留理解为 OBS，文中统一术语为 OBS。

### Q37. 两个 M10/M11 候选交叠区域是否代表两个 TSV

**问题：**

**解答：**

如果有两块重叠，一般是在pin上重叠，这种不会直接在pin上打TSV，会走线走到另外一个地方再打TSV，会对这里进行判断，如果有其中有一个 TSV 是刚好覆盖到 pin 上面的话，我们就会把 pin 上面那个 TSV 去掉，所以还是一个 TSV。只不过允许在这种情况下有两个TSV，官方会把有pin的那个TSV去掉。如果两个pin都不是覆盖在pin那里，也是违规的。

**来源：** 官方 Q&A（原 Q103）。

**补充说明：**

原答复末句“如果两个pin都不是覆盖在pin那里，也是违规的”指代不够严谨。结合前文可读为两个候选都不覆盖 Pin 时不合法；该解读需以正式实现为准，不把两个候选写成允许两个实际 TSV。

不可以。除非是网络不稳定等其他原因造成的，会重新评测。hidden case在规模大小、难度上不会和public相差过多，评分规则是统一的。
